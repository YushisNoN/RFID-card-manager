# RFID Card Manager (Rfid Module) — ESP32 Firmware

Прошивка контроллера ESP32 для системы RFID Card Manager. Контроллер считывает UID RFID-карты с помощью модуля RC522, отображает состояние операции на TFT-дисплее и отправляет UID на HTTP-сервер для обработки и учёта выдачи/возврата плат.

Прошивка является аппаратной частью проекта RFID Card Manager. Серверная часть написана на Zig и использует PostgreSQL; её настройка и развёртывание описаны в README соответствующей серверной ветки репозитория.

> **Статус проекта:** в разработке. Описание ниже отражает текущую реализацию прошивки и её интерфейсов с сервером.

## Возможности

- Считывание UID RFID-карт с помощью RC522.
- Передача UID на сервер методом HTTP POST в формате JSON.
- Подключение к Wi-Fi в режиме станции (STA).
- Создание собственной точки доступа для первоначальной настройки Wi-Fi (AP).
- Настройка SSID и пароля через веб-страницу, размещённую непосредственно на ESP32.
- Сохранение параметров Wi-Fi в энергонезависимой памяти NVS.
- Автоматическая загрузка сохранённых параметров и попытка подключения к сети после перезапуска.
- Отображение состояний ожидания, проверки, успешной операции и ошибки на TFT-дисплее.
- Анимации графического интерфейса на базе LVGL.

## Архитектура

Прошивка состоит из четырёх основных частей:

1. **`main.c`** — точка входа приложения. Инициализирует NVS, дисплей и GUI, Wi-Fi, затем RFID-считыватель.
2. **RFID-модуль (`RFID.c`, `RFID.h`)** — инициализирует RC522, обрабатывает события обнаружения карты, извлекает UID и передаёт его сетевому модулю.
3. **Сетевой модуль (`web.c`, `web.h`)** — создаёт точку доступа `RFID-Setup`, предоставляет веб-страницу настройки Wi-Fi, сохраняет учётные данные в NVS и отправляет UID на сервер.
4. **GUI-модуль (`gui.c`, `gui.h`)** — инициализирует дисплей ST7789V и LVGL, создаёт интерфейс и предоставляет функции переключения его состояний.

Общая последовательность запуска:

```text
ESP32 включается
       |
       v
Инициализация NVS
       |
       v
Инициализация TFT и LVGL
       |
       v
Запуск Wi-Fi AP + STA
       |
       +---- Учётные данные Wi-Fi отсутствуют
       |          |
       |          v
       |     Настройка через RFID-Setup
       |          |
       |          v
       |     Сохранение в NVS и перезапуск
       |
       v
Попытка подключения к сохранённой Wi-Fi сети
       |
       v
Инициализация RC522
       |
       v
Обнаружение RFID-карты
       |
       v
Получение UID и отправка HTTP POST
       |
       v
Отображение результата на TFT
```

`wifi_init_sta()` не ожидает подключения к маршрутизатору бесконечно. Поэтому инициализация RFID продолжается, даже если сеть ещё не настроена или временно недоступна. Перед отправкой запроса `sendRequest()` ожидает подключения до пяти секунд.

## Аппаратная часть

Текущая конфигурация проекта рассчитана на следующую аппаратную часть:

| Компонент | Назначение |
|---|---|
| ESP32 DevKit V1 / ESP32-D0WD-V3 | Основной микроконтроллер |
| RC522 | Считывание RFID-карт по SPI |
| TFT Touch Display 2.8" v1.1 | Вывод графического интерфейса |
| ST7789V | Контроллер TFT-дисплея |

В используемой конфигурации дисплей имеет разрешение **240 × 320 пикселей**. Сенсорный ввод в текущем описанном программном интерфейсе не используется.

## Распиновка

### RC522 — SPI2_HOST

| Сигнал RC522 | GPIO ESP32 | Назначение |
|---|---:|---|
| MISO | GPIO19 | Данные от RC522 к ESP32 |
| MOSI | GPIO23 | Данные от ESP32 к RC522 |
| SCK / SCLK | GPIO18 | Тактовый сигнал SPI |
| SDA / SS / CS | GPIO21 | Выбор SPI-устройства |
| RST | GPIO22 | Сброс считывателя |

Настройки расположены в `main/rfid/RFID.c` в макросах `RC522_SPI_BUS_GPIO_*`, `RC522_SPI_SCANNER_GPIO_SDA` и `RC522_SCANNER_GPIO_RST`.

### TFT ST7789V — SPI3_HOST

| Сигнал дисплея | GPIO ESP32 | Назначение |
|---|---:|---|
| CS | GPIO15 | Выбор дисплея |
| DC | GPIO2 | Выбор команды или данных |
| RESET | GPIO4 | Сброс дисплея |
| MOSI | GPIO12 | Данные ESP32 к дисплею |
| SCK / SCLK | GPIO13 | Тактовый сигнал SPI |
| MISO | GPIO14 | Линия MISO |

Настройки расположены в `main/gui/gui.c` в макросах `PIN_NUM_*` и `LCD_HOST`.

> Перед подключением оборудования проверьте маркировку конкретных плат модулей, допустимое напряжение питания и уровни логических сигналов. У ESP32, RC522 и дисплея должна быть общая земля (GND). GPIO, занятые периферией, не следует использовать для других целей без изменения конфигурации прошивки.

## Требования

Для сборки прошивки необходимы:

- плата ESP32 с физической SPI Flash объёмом **не менее 4 МБ**; для описанной конфигурации проекта используется Flash объёмом **4 МБ**;
- ESP-IDF 6.1.x;
- Python-окружение, установленное ESP-IDF Installer;
- CMake и Ninja из комплекта ESP-IDF;
- USB-драйвер платы и доступный COM-порт;
- компоненты, указанные в `main/idf_component.yml`;
- подключённые RC522 и TFT-дисплей с указанной распиновкой.

Для работы системы также требуется доступный HTTP-сервер RFID Card Manager. Сервер должен быть достижим из Wi-Fi сети, к которой подключается ESP32.

## Настройка Flash, таблицы разделов и стека

Для текущей сборки необходимо согласовать три параметра ESP-IDF: фактический объём Flash, пользовательскую таблицу разделов и размер стека главной задачи. Без этой настройки сборка может завершиться ошибкой проверки размера приложения либо работать нестабильно при инициализации.

### 1. Проверка физического объёма Flash

В используемой аппаратной конфигурации ESP32 обнаружена Flash-память объёмом **4 МБ**. Проверить объём памяти подключённой платы можно командой (замените `COM3` на фактический COM-порт):

```powershell
python -m esptool --port COM3 flash-id
```

В выводе ожидается строка:

```text
Detected flash size: 4MB
```

У разных модулей ESP32 объём Flash может отличаться. Не выбирайте в настройках ESP-IDF объём больше физически установленного на плате. Если команда показывает другое значение, необходимо адаптировать размер Flash и таблицу разделов под конкретный модуль.

### 2. Создание `partitions.csv`

В корне проекта, рядом с корневым `CMakeLists.txt`, создайте файл `partitions.csv` со следующим содержимым:

```csv
# Name,     Type, SubType, Offset,   Size,     Flags
nvs,        data, nvs,     0x9000,   0x6000,
phy_init,   data, phy,     0xf000,   0x1000,
factory,    app,  factory, 0x10000,  0x200000,
```

Назначение разделов:

| Раздел | Смещение | Размер | Назначение |
|---|---:|---:|---|
| `nvs` | `0x9000` | `0x6000` (24 КБ) | Хранение настроек Wi-Fi, записываемых через NVS API |
| `phy_init` | `0xF000` | `0x1000` (4 КБ) | Раздел для PHY init data, если соответствующая настройка ESP-IDF включена |
| `factory` | `0x10000` | `0x200000` (2 МБ) | Основное приложение ESP32 |

Текущая таблица предусматривает один раздел приложения `factory` и **не содержит OTA-разделов**. Она также не резервирует отдельный раздел под SPIFFS или LittleFS. Если в дальнейшем потребуется OTA-обновление или файловая система во Flash, таблицу необходимо переработать с учётом этих требований.

### 3. Выбор пользовательской таблицы разделов

Откройте конфигурацию проекта:

```powershell
idf.py menuconfig
```

В меню `Partition Table` установите:

- `Partition Table` → `Custom partition table CSV`;
- `Custom partition CSV file` → `partitions.csv`.

Путь задаётся относительно корня проекта. После сохранения конфигурации ESP-IDF будет использовать созданный CSV-файл при генерации бинарной таблицы разделов.

### 4. Настройка размера Flash в ESP-IDF

В том же `menuconfig` откройте `Serial flasher config` и установите:

- `Flash size` → `4 MB`.

Это значение должно совпадать с результатом `flash-id` и физическим объёмом памяти модуля. Если оставить настройку `2 MB`, сборка может завершиться сообщением о том, что таблица разделов занимает больше доступной Flash-памяти. Увеличение значения в меню не увеличивает физическую память микроконтроллера.

### 5. Увеличение размера стека главной задачи до 8192 байт

Для используемой конфигурации проекта размер стека главной задачи ESP-IDF следует установить в **8192 байта (8 КиБ)**. Эта задача вызывает `app_main()`.

Откройте:

```powershell
idf.py menuconfig
```

Перейдите в раздел:

`Component config` → `ESP System Settings` → `Main task stack size`

Установите значение:

```text
8192
```

Параметр в `sdkconfig` называется `CONFIG_ESP_MAIN_TASK_STACK_SIZE`. После сохранения можно проверить его значение в PowerShell:

```powershell
Select-String -Path sdkconfig -Pattern '^CONFIG_ESP_MAIN_TASK_STACK_SIZE='
```

Ожидаемая строка:

```text
CONFIG_ESP_MAIN_TASK_STACK_SIZE=8192
```

> Это размер стека именно главной задачи, которая выполняет `app_main()`. Он не меняет размер стека задач Wi-Fi, HTTP-сервера, LVGL или других компонентов ESP-IDF: у этих задач собственные настройки.

Чтобы значение применялось как настройка по умолчанию при создании конфигурации нового клона проекта, его можно добавить в корневой `sdkconfig.defaults` вместе с параметрами Flash и таблицы разделов:

```ini
CONFIG_ESPTOOLPY_FLASHSIZE_4MB=y
CONFIG_PARTITION_TABLE_CUSTOM=y
CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions.csv"
CONFIG_ESP_MAIN_TASK_STACK_SIZE=8192
```

`sdkconfig.defaults` задаёт значения по умолчанию при формировании `sdkconfig`. Если в рабочем каталоге уже существует `sdkconfig`, проверьте и измените его через `idf.py menuconfig`; простое добавление строки в defaults не следует считать заменой проверки текущей конфигурации.

### 6. Проверка таблицы и сборка

После сохранения настроек выполните:

```powershell
idf.py reconfigure
idf.py partition-table
idf.py build
```

Команда `idf.py partition-table` выводит фактически сформированную таблицу. Проверьте, что приложение `factory` имеет размер `0x200000`, а таблица не выходит за пределы физической Flash. Если сборка ранее выполнялась с другой таблицей или размером Flash и возникли конфликты устаревшей конфигурации, выполните полную очистку и повторную конфигурацию:

```powershell
idf.py fullclean
idf.py reconfigure
idf.py partition-table
idf.py build
```

При смене таблицы разделов данные в Flash по прежним адресам могут быть несовместимы с новой разметкой. При необходимости выполните полную очистку Flash командой `idf.py erase-flash`, учитывая, что она удалит сохранённые настройки Wi-Fi в NVS.

Дополнительная информация: [Partition Tables в документации ESP-IDF 6.1](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-guides/partition-tables.html), [Freertos — задачи ESP-IDF](https://documentation.espressif.com/projects/esp-idf/en/v6.1/esp32/api-reference/system/freertos.html).

## Первичная настройка Wi-Fi

Прошивка создаёт собственную точку доступа, чтобы сеть можно было настроить без изменения исходного кода и повторной прошивки.

### Параметры точки доступа

| Параметр | Значение по умолчанию |
|---|---|
| SSID | `RFID-Setup` |
| Пароль | Значение `SETUP_AP_PASSWORD` в `web.c` |
| IP-адрес ESP32 | `192.168.4.1` |
| HTTP-порт | `80` |
| Страница настройки | `http://192.168.4.1/` |

В текущем исходном коде тестовое значение `SETUP_AP_PASSWORD` задано как `rfidsetup`. Не используйте один пароль для точки доступа настройки и основной Wi-Fi сети.

### Порядок настройки

1. Включите ESP32.
2. На телефоне или компьютере откройте список доступных Wi-Fi сетей.
3. Подключитесь к точке доступа `RFID-Setup`, используя пароль, заданный в `SETUP_AP_PASSWORD`.
4. Устройство может сообщить, что у этой сети нет доступа к Интернету. Оставайтесь подключёнными к точке доступа ESP32.
5. Откройте браузер и перейдите по адресу `http://192.168.4.1/`.
6. Введите SSID и пароль маршрутизатора, к которому должен подключиться терминал.
7. Нажмите кнопку сохранения.
8. После успешной записи параметров в NVS ESP32 отправит страницу подтверждения и перезапустится.
9. После перезапуска контроллер загрузит сохранённые параметры и попытается подключиться к выбранной Wi-Fi сети.

Точка `RFID-Setup` запускается в режиме AP + STA и остаётся включённой после подключения к маршрутизатору. Поэтому страницу настройки можно открыть повторно, подключившись к точке доступа ESP32.

### Что происходит при ошибке подключения

Если SSID или пароль введены неправильно, ESP32 не сможет получить IP-адрес маршрутизатора. Точка `RFID-Setup` при этом остаётся доступной, поэтому можно повторно открыть страницу и сохранить корректные параметры.

Веб-форма отправляет данные методом `POST` на маршрут `/save`. Значения формы перед сохранением декодируются из формата `application/x-www-form-urlencoded` и записываются в NVS.

## Подключение к серверу

Адрес сервера задаётся в `main/web-client/web.c` в параметре `SERVER_URL`:

```c
static const char *SERVER_URL =
    "http://<SERVER_IP>/api/checkUID";
```

Укажите IP-адрес или доменное имя сервера, доступное из сети ESP32.

Согласно конфигурации серверной ветки, Zig-сервер слушает порт `8080` внутри контейнера, а Docker публикует его на порт `80` хоста. Поэтому при таком развёртывании адрес обычно имеет вид:

```text
http://<SERVER_IP>/api/checkUID
```

Если сервер запущен непосредственно на машине без публикации порта `80:8080`, укажите фактический порт, например:

```text
http://<SERVER_IP>:8080/api/checkUID
```

Важно: ESP32 и сервер должны иметь сетевую связность. Если сервер находится за NAT или межсетевым экраном, необходимо разрешить доступ к соответствующему адресу и порту.

## Работа RFID-модуля

Модуль RC522 подключается к ESP32 по SPI2_HOST. После вызова `RFIDinit()` создаётся SPI-драйвер, устанавливается драйвер RC522, создаётся экземпляр считывателя, регистрируется обработчик `on_picc_state_changed()` и запускается сканирование.

При событии изменения состояния карты обработчик:

1. Проверяет, что карта перешла в состояние `RC522_PICC_STATE_ACTIVE`.
2. Выводит сведения о карте в журнал ESP-IDF.
3. Переключает GUI в состояние проверки.
4. Проверяет совместимость типа карты с MIFARE Classic.
5. Пытается авторизовать и прочитать блок `1` с использованием стандартного ключа MIFARE, заданного компонентом RC522. Результат чтения выводится в журнал; ошибка чтения блока сама по себе не отменяет отправку UID.
6. Выполняет деавторизацию MIFARE.
7. Копирует UID в структуру `RFIDCard`.
8. Передаёт UID в `sendRequest()`.
9. В зависимости от результата HTTP-запроса показывает успешное состояние или ошибку.

Структура передачи UID объявлена в `RFID.h`:

```c
typedef struct {
    uint8_t size;
    uint8_t bytes[10];
} RFIDCard;
```

`size` содержит фактическое количество байтов UID, а `bytes` — сами байты UID. Перед отправкой проверяется, что длина UID не превышает размер массива.

## Графический интерфейс

Дисплей ST7789V и графическая библиотека LVGL инициализируются функцией `gui_init()`.

| Состояние | Функция | Отображение |
|---|---|---|
| Ожидание карты | `gui_show_waiting()` | Предложение приложить карту, голубая анимация |
| Проверка карты | `gui_show_reading()` | Сообщение о проверке, анимация индикатора |
| Успешный ответ | `gui_show_success()` | Зелёная индикация, сообщение об успешной операции |
| Ошибка | `gui_show_error()` | Красная индикация, сообщение о повторной попытке |

После успешного ответа состояние отображается около пяти секунд, после ошибки — около трёх секунд, затем интерфейс возвращается к ожиданию.

Для текстовых элементов используется пользовательский шрифт `rfid_font_18`, сгенерированный в формате LVGL C. Файл шрифта должен быть включён в сборку компонента `main`.

## Формат HTTP-запроса

ESP32 отправляет UID методом `POST` на `SERVER_URL` с заголовком `Content-Type: application/json`.

Пример тела запроса:

```http
POST /api/checkUID HTTP/1.1
Content-Type: application/json

{
  "size": 4,
  "bytes": [4, 123, 22, 89]
}
```

| Поле | Тип | Описание |
|---|---|---|
| `size` | число | Количество значимых байтов UID |
| `bytes` | массив чисел | Байты UID; сервер должен обработать первые `size` элементов |

### Обработка HTTP-ответа в прошивке

Текущая реализация `sendRequest()` считает запрос успешным только при следующих условиях:

- HTTP-клиент успешно выполнил запрос;
- сервер вернул статус **HTTP 200**.

При сетевой ошибке, тайм-ауте или любом другом HTTP-статусе функция возвращает ошибку. Ответное JSON-тело серверной части в текущей реализации ESP32 не разбирается.

Поэтому если сервер возвращает HTTP 200 и разные значения `status` для выдачи и возврата, дисплей пока показывает общее сообщение об успешной обработке. Для разных сообщений, например «Плата выдана» и «Плата возвращена», потребуется добавить разбор JSON-ответа в `sendRequest()` и расширить интерфейс между сетевым модулем и GUI.

## Хранение настроек

Учётные данные Wi-Fi хранятся в NVS в пространстве имён `wifi_cfg`:

| Ключ | Тип NVS | Назначение |
|---|---|---|
| `ssid` | Строка | Имя Wi-Fi сети |
| `password` | Строка | Пароль Wi-Fi сети |

При запуске `load_wifi_credentials()` читает эти значения. Если SSID найден, прошивка конфигурирует интерфейс STA и запускает подключение после события `WIFI_EVENT_STA_START`.

При отправке новой формы `save_handler()` записывает оба значения и вызывает `nvs_commit()`. После успешной отправки страницы подтверждения контроллер перезапускается.

NVS инициализируется в `main.c`. Если обнаружены `ESP_ERR_NVS_NO_FREE_PAGES` или `ESP_ERR_NVS_NEW_VERSION_FOUND`, код очищает раздел NVS и инициализирует его повторно. Очистка NVS удалит и сохранённые параметры Wi-Fi.

## Настройка дисплея и шрифта

Основные параметры дисплея заданы в `main/gui/gui.c`:

- SPI host: `SPI3_HOST`;

- формат пикселя: `RGB565`;

Для изменения ориентации и подключения дисплея следует проверить GPIO-макросы и параметры `esp_lcd_panel_mirror()` и `lvgl_port_display_cfg_t`.

### Пользовательский шрифт

```c
LV_FONT_DECLARE(rfid_font_18);
```

Сгенерированный файл `rfid_font_18.c` необходимо добавить в `SRCS` файла `main/CMakeLists.txt`, например:

idf_component_register(

        "main.c"
        "rfid/RFID.c"

        "gui/rfid_font_18.c"

        "."
        "rfid"

Шрифт должен включать используемые символы латиницы и кириллицы, включая `Ё` и `ё`. Для корректного отображения русских строк LVGL должен быть настроен на UTF-8, а исходники с русскими строками — сохранены в UTF-8.

## Решение частых проблем

### ESP32 не подключается к Wi-Fi

- Убедитесь, что SSID и пароль введены без ошибок.
- Проверьте, что используемая сеть доступна в диапазоне и режиме, поддерживаемом ESP32.
- Подключитесь к `RFID-Setup` и повторно откройте `http://192.168.4.1/`.
- Проверьте сообщения `Wi-Fi disconnected` и `Connected! IP` в последовательном мониторе.
- Помните, что `sendRequest()` ожидает подключения не более пяти секунд.

### Страница настройки не открывается

- Убедитесь, что компьютер или телефон подключён именно к `RFID-Setup`.
- Откройте адрес `http://192.168.4.1/` вручную.
- Не используйте `https://` для локальной страницы настройки.
- Проверьте по монитору, что точка доступа и HTTP-сервер успешно запущены.

### Сервер не получает UID

- Проверьте значение `SERVER_URL`.
- Убедитесь, что ESP32 подключена к сети и получила IP-адрес.
- Проверьте доступность сервера и опубликованного HTTP-порта.
- Убедитесь, что сервер принимает `POST /api/checkUID` и JSON с полями `size` и `bytes`.
- Проверьте журнал ESP-IDF на сообщения `HTTP request failed` и `HTTP Status`.

### На дисплее не отображается кириллица

- Убедитесь, что `rfid_font_18.c` добавлен в `SRCS`.
- Проверьте, что файл шрифта действительно содержит диапазоны кириллических символов.
- Проверьте `LV_FONT_DECLARE(rfid_font_18)` и использование `&rfid_font_18` для русскоязычных меток.
- Проверьте настройку UTF-8 в конфигурации LVGL.
- Сохраните `gui.c` в кодировке UTF-8.

### Ошибка размера раздела приложения

Размер приложения может превышать размер раздела `factory`. Проверьте конфигурацию Flash и таблицу разделов через `idf.py menuconfig`. Физический размер Flash должен соответствовать настройке ESP-IDF, а раздел приложения должен вмещать собранный бинарный файл.

## Текущие ограничения и безопасность

- **Нет сканирования сетей в форме настройки.** SSID вводится вручную; список доступных сетей текущая страница не показывает.
- **Точка настройки остаётся включённой.** Используется режим AP + STA. Это упрощает повторную настройку, но увеличивает доступную поверхность подключения.
- **Тестовый пароль точки доступа.** Значение `SETUP_AP_PASSWORD` необходимо изменить перед использованием устройства вне лабораторной среды.
- **Нет HTTPS.** Страница настройки и запрос к серверу используют HTTP. Не передавайте через недоверенные сети конфиденциальные данные без дополнительной защиты.
- **Нет отдельной авторизации веб-страницы настройки.** Доступ контролируется паролем Wi-Fi точки доступа.
- **Учётные данные хранятся в NVS.** В текущей конфигурации приложения отдельно не настраивается шифрование NVS.
- **Адрес сервера задаётся в исходном коде.** Перед сборкой для другой сети требуется изменить `SERVER_URL`.
- **HTTP JSON-ответ не разбирается.** Прошивка проверяет HTTP-статус, но не использует поля `status`, `allowed` или `message` из тела ответа.
- **Обработка RFID ограничена совместимыми с MIFARE Classic типами.** В текущем `RFID.c` присутствует проверка `rc522_mifare_type_is_classic_compatible()`.
- **Чтение блока 1 является дополнительной операцией.** Результат чтения выводится в лог; после этого UID всё равно отправляется на сервер.
- **Повторные события RC522 отдельно не блокируются.** При повторном событии активного состояния карта может быть отправлена на сервер повторно. Защиту от дублирования следует реализовать отдельно, если она требуется сценарию эксплуатации.
- **Обработка ошибок инициализации RC522 требует усиления.** В текущем варианте `RFIDinit()` не проверяет возвращаемые значения всех вызовов инициализации компонента.
