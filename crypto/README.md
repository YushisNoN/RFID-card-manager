# Используемые алгоритмы криптографии, их описание и применение

## Challenge-response

Интерактивный протокол взаимной аутентификации. Работает по следующему принципу:

Клиент, в данном случае метка, генерирует challange для сервера. Сервер, в данном случае ESP32, генерирует response на основе секретного ключа, отправляя его уже как challenge для клиента. Клиент валидирует полученное сообщение и генерирует response, шифруя challange специальным способом на основе секретного ключа. Сервер валидирует полученный response. 

Для реализации этого механизма необходимо обеспечить:

1. Генерацию случайных чисел для challenge (есть в ESP32).
2. Хранение секретного ключа меткой в защищённой памяти.
3. Хранение секретного ключа контроллером в защищённой памяти.
4. Запись секретного ключа на метку.
5. Генерацию response на основе секретного ключа и значений challenge меткой.
6. Валидацию challenge меткой.
7. Валидацию response (легко обеспечить в ESP32).
8. Защиту от replay-атак путём использования nonce.

### Математика процесса

**Обозначения:**

- `K` — общий секретный ключ (24 байта, 3DES).
- `RndA` — случайное число (nonce) считывателя (8 байт).
- `RndB` — случайное число (nonce) метки (8 байт).
- `E_k(X)` — шифрование 3DES ключом `K`.
- `D_k(X)` — расшифровка 3DES ключом `K`.
- `ShiftLeft(X)` — циклический сдвиг влево на 1 байт.
- `||` — конкатенация.

**Шаг 1. Метка → Считыватель**
token_1 = E_k(RndB)

Метка генерирует `RndB`, шифрует его ключом `K` и отправляет считывателю.

**Шаг 2. Считыватель → Метка**

Считыватель расшифровывает `token_1` и извлекает `RndB`:
RndB = D_k(token_1)

Вычисляет сдвинутое значение:
RndB' = ShiftLeft(RndB)

Генерирует свой nonce `RndA`. Формирует два блока в режиме CBC:
C_1 = E_k(RndA)
C_2 = E_k(RndB' xor C_1)

Отправляет метке конкатенацию:
token_2 = C_1 || C_2

**Шаг 3. Проверка на стороне метки**

Метка получает `token_2` (16 байт), разбивает его на `C_1` (первые 8 байт) и `C_2` (вторые 8 байт).

Извлекает `RndA` считывателя:
RndA = D_k(C_1)

Восстанавливает `RndB'` с использованием CBC-цепочки:
RndB'_received = D_k(C_2) xor C_1

Проверяет:
RndB'_received == ShiftLeft(RndB) ?

Если равенство выполняется — считыватель доказал знание ключа `K`.

**Шаг 4. Метка → Считыватель**

Метка вычисляет сдвинутое `RndA`:
RndA' = ShiftLeft(RndA)

Шифрует и отправляет:
token_3 = E_k(RndA')

**Шаг 5. Проверка на стороне считывателя**

Считыватель расшифровывает `token_3`:
RndA'_received = D_k(token_3)

Сравнивает с собственным исходным `RndA`:
RndA'_received == ShiftLeft(RndA) ?

Если равенство выполняется — метка доказала знание ключа `K`. Взаимная аутентификация завершена успешно.

## TLS 

Поддерживается на уровне ESP32. Достаточно использовать WiFiClientSecure вместо WiFiClient и обеспечить:

На сервере — сертификат сервера и приватный ключ.

На ESP32 — корневой CA-сертификат (через setCACert()), которым подписан сертификат сервера.
